## Описание проекта
**NotesApp** — это полноценное REST API приложение для управления заметками по категориям. Проект представляет собой серверную часть (бэкенд) для приложения-блокнота, где пользователи могут:
- **Создавать категории** (Работа, Учёба, Личное и т.д.) с цветовой маркировкой
- **Создавать заметки** с заголовком, содержимым и приоритетом
- **Закреплять важные заметки** (показываются вверху списка)
- **Архивировать заметки** (скрываются из основного списка)
- **Фильтровать заметки** по категории, приоритету, поиску по тексту
- **Сортировать заметки** по заголовку, приоритету, дате создания/обновления
- **Пагинация** для эффективной работы с большим количеством данных

## Паттерн Repository
**Repository (Репозиторий)** — это паттерн проектирования, который создаёт слой абстракции между логикой приложения (контроллерами) и логикой доступа к данным (DbContext).
```
Без Repository:
Контроллер → DbContext → База данных

С Repository:
Контроллер → Repository → DbContext → База данных
```
| Проблема без Repository | Решение с Repository |
|------------------------|---------------------|
| Логика запросов к БД размазана по контроллерам | Все запросы собраны в одном месте |
| Трудно тестировать контроллер отдельно от БД | Можно подменить репозиторий на тестовый мок |
| При смене БД нужно менять все контроллеры | Меняется только реализация репозитория |
| Дублирование одинаковых запросов | Переиспользуемые методы |

## Главные выводы
1. Паттерн Repository — не лишняя абстракция, а способ держать код управляемым при росте проекта.
2. Data Annotations решают двойную задачу: валидируют входные данные и задают ограничения в БД.
3.  Единый формат ответа (ApiResponse) упрощает жизнь фронтенду — он всегда знает, что ждать от сервера.
4. DeleteBehavior.Restrict защищает данные от случайного каскадного удаления.
5. Include() и проекция в DTO через Select() — правильный способ получить связанные данные без N+1 проблемы.
